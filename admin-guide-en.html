Chapter 1

Administrator Overview

This guide is intended for system administrators of the Lobato Tours Quotation System. It covers user management, role configuration, system setup, the database schema, and the REST API.

Admin dashboard — full statistics and monthly trend chart

As an administrator, you have full access to all features of the application plus exclusive access to:

Admin-Only FeatureDescriptionURL
👥 User ManagementCreate, edit, deactivate, and delete user accounts/admin/users
📊 All QuotesView and manage every quote in the system (not just your own)/cotizaciones
⚙️ System InitInitialize or reset the database via the API/api/init
📤 Full CSV ExportExport all quotes across all users/api/cotizaciones/export
🛡️
Admin Access is Protected

Admin-only routes (like /admin/users) redirect non-admin users back to the dashboard automatically. The API enforces role checks server-side on every request.

Chapter 2

Roles & Permissions

The system uses three role levels. Each role controls what a user can see and do.

👑
Administrator
Internal code: admin
  • Access all quotes from all users
  • Create, edit, deactivate, and delete user accounts
  • Access the /admin/users page
  • Initialize and manage the database
  • Export all system data
  • All Manager and User permissions
🎯
Manager
Internal code: manager
  • View and manage all quotes from all users
  • Export CSV of all quotes
  • Create and manage their own quotes
  • Cannot access user management
  • Cannot delete other users' accounts
👤
User
Internal code: user
  • Create, view, edit, and delete their own quotes
  • Export their own quotes to CSV
  • Cannot view other users' quotes
  • Cannot access admin panel
  • Cannot manage users
⚠️
Default credentials

The initial admin account created during database setup uses username: admin and password: admin123. Change this password immediately after first login in production.

Click the + New User button on the User Management page to open the Create User modal.

  1. 1

  2. 2

    Fill in required fields

    Enter username, full name, email, and a temporary password. Phone is optional.

  3. 3

  4. 4

    Click "Create User"

    The new account is created immediately. Share the username and temporary password with the user securely.

🔒
Security Best Practice

Set a temporary password and ask the user to change it on first login. Do not reuse passwords across accounts.

Chapter 3.3

Deactivating & Deleting Users

There are two ways to remove a user's access: deactivation (reversible) and deletion (permanent).

Deactivating a User

Click the green Active status badge in the users table to toggle it to Inactive. The user will be prevented from logging in, but their account and all their quotes remain intact.

💡

Prefer deactivation over deletion for employees who leave the company. Their historical quotes remain accessible to managers and admins, preserving important business records.

Deleting a User

Click the red Delete button on a user's row. A confirmation dialog will appear showing the user's name and username. Click Eliminar to permanently delete the account.

🚨
Deletion is permanent

Deleting a user account cannot be undone. All their quotes will remain in the system attributed to their employee ID, but they will no longer be able to log in and their profile information will be removed. The delete button is not available for the currently logged-in admin.

Chapter 4

Managing All Quotes (Admin View)

Unlike regular users who only see their own quotes, Admins and Managers see all quotes from all agents in the Quotes List.

Admin/Manager view — all quotes from every agent are visible

From /cotizaciones, admins can:

  • View, edit, duplicate, and delete any quote regardless of who created it
  • Search and filter across all customer names, statuses, and dates
  • Export the full dataset to CSV for reporting
ℹ️

The server-side logic automatically checks the logged-in user's role on every API call. Admins and Managers automatically receive unfiltered data; regular Users receive only their own records.

Chapter 4.1

Export & Reporting

The CSV export allows you to pull all quote data into a spreadsheet for analysis, reporting, or archiving.

Exporting from the UI

On the Quotes List page, click Export CSV. The download respects the active filters — if you want all quotes, clear all filters first.

Exporting via API

GET/api/cotizaciones/export

# Optional query parameters:
?status=all|finished|draft
?search=customer_name_or_phone
?sortBy=id|creation_date|finished
?sortOrder=ASC|DESC

The response is a text/csv file with all matching quotes. The export includes customer name, contact, destination, travel dates, status, and creation date.

Chapter 7

API Reference

The application exposes a REST API under /api. All endpoints require a valid session cookie (set by the login endpoint).

Authentication

POST/api/auth/login — Log in. Body: { username, password }
GET  /api/auth/me — Get current session info (id, role)
POST/api/auth/logout — Log out and clear session

Dashboard

GET  /api/dashboard — Returns stats: totals, thisMonth, growth, expiringSoon, recentQuotes, monthlyTrend

Quotes (Cotizaciones)

GET  /api/cotizaciones — List quotes (paginated). Params: page, search, status, sortBy, sortOrder, limit
GET  /api/cotizacion/[id] — Get a single quote with all nested data
POST/api/cotizacion/[id] — Create or update a quote (upsert)
DEL  /api/cotizacion/[id] — Delete a quote (Admin/Manager: any; User: own only)
POST/api/cotizacion/[id]/duplicate — Create a copy of the quote as a new draft
GET  /api/cotizaciones/export — Download filtered quotes as CSV file

Users

GET  /api/users — List all users. Admin only.
POST/api/users — Create a new user. Admin only. Body: { user_name, real_name, email, password, role, phone_number? }
PUT  /api/users/[id] — Update user fields. Admin only. Body: any editable fields.
DEL  /api/users/[id] — Delete user account. Admin only. Cannot delete own account.

Database Initialization

GET  /api/init — Check if tables exist and return database status
POST/api/init — Create all tables and seed the default admin user
⚠️

The POST /api/init endpoint is safe to call multiple times (it uses CREATE TABLE IF NOT EXISTS), but restrict access to it in production via middleware or firewall rules.

Chapter 9

First-Time Setup

Follow these steps to set up the Lobato Tours system from scratch on a new machine.

  1. 1

    Prerequisites

    Install Node.js (v18+), npm, and Docker Desktop on the server or development machine.

  2. 2

    Clone the repository and install dependencies

    Run npm install in the project directory to install all Node.js packages.

  3. 3

    Create the .env file

    Copy the environment variables from Chapter 5 into a new .env file at the project root. Update NEXTAUTH_SECRET with a strong random value.

  4. 4

    Start the database container

    Run npm run docker:up. Wait a few seconds for PostgreSQL to be ready.

  5. 5

    Start the development server

    Run npm run dev. The application starts on http://localhost:3000.

  6. 6

    Initialize the database

    Visit http://localhost:3000. If tables don't exist, send a POST request to /api/init (or run npm run init-db). This creates all tables and the default admin account.

  7. 7

    Log in and change the admin password

    Log in with admin / admin123. Go to User Management and edit the admin account to set a secure password immediately.

🚀
Automated Setup

Run npm run setup to execute steps 4–6 automatically with a single command.

Chapter 10

Troubleshooting

Common issues and their solutions.

🔴 Cannot connect to database

  • Run docker ps to confirm the container is running
  • Verify DB_PORT in .env matches the docker-compose host port (5430)
  • Check for port conflicts: lsof -i :5430
  • Run npm run docker:logs to see PostgreSQL startup errors

🟡 Tables not created / "relation does not exist"

  • Send POST /api/init to create all tables
  • Or run: npm run init-db
  • Check the browser console for API errors and verify DB connection first

🟡 Login failing with correct credentials

  • Verify NEXTAUTH_SECRET is set in .env
  • Clear browser cookies and try again
  • Confirm NEXTAUTH_URL matches the URL you're accessing in the browser

🟡 /admin/users redirects to dashboard

  • Your account does not have the Admin role
  • Log in with an Admin account, or ask another admin to upgrade your role

🟢 Permission errors on startup script

  • Run: chmod +x scripts/start-dev.sh
Chapter 11

Security Notes

Key security practices for operating the Lobato Tours system.

Authentication & Sessions

  • Sessions are stored server-side, signed with NEXTAUTH_SECRET. Use a minimum 32-character random secret in production.
  • Passwords are hashed with bcrypt before storage. Plain-text passwords are never logged or stored.
  • Role checks are enforced on every API call server-side — they cannot be bypassed by modifying cookies or URLs.

Production Checklist

Default admin passwordChange immediately after first setup
NEXTAUTH_SECRETUse openssl rand -hex 32 to generate

🛡️
Sensitive Data

Quote data may contain personal customer information (names, phone numbers, email). Ensure the production server is compliant with applicable data protection regulations (e.g., GDPR, LFPDPPP in Mexico).
