Capítulo 1

Visión General del Administrador

Esta guía está dirigida a los administradores del Sistema de Cotizaciones de Lobato Tours. Cubre la gestión de usuarios, configuración de roles, instalación del sistema, esquema de base de datos y la API REST.

Panel de inicio del Administrador — estadísticas completas y tendencia mensual

Como administrador, tienes acceso total a todas las funciones de la aplicación, más acceso exclusivo a:

Función Exclusiva de AdminDescripciónURL
👥 Gestión de UsuariosCrear, editar, desactivar y eliminar cuentas de usuario/admin/users
📊 Todas las CotizacionesVer y gestionar todas las cotizaciones del sistema (no solo las propias)/cotizaciones
⚙️ Inicialización del SistemaInicializar o restablecer la base de datos via API/api/init
📤 Exportación Completa CSVExportar todas las cotizaciones de todos los usuarios/api/cotizaciones/export
🛡️
El Acceso de Admin está Protegido

Las rutas exclusivas de administrador (como /admin/users) redirigen automáticamente a usuarios sin rol admin al Panel de Control. La API verifica los roles del lado del servidor en cada solicitud.

Capítulo 2

Roles y Permisos

El sistema utiliza tres niveles de rol. Cada rol controla lo que un usuario puede ver y hacer.

👑
Administrador
Código interno: admin
  • Acceso a todas las cotizaciones de todos los usuarios
  • Crear, editar, desactivar y eliminar cuentas de usuario
  • Acceso a la página /admin/users
  • Inicializar y administrar la base de datos
  • Exportar todos los datos del sistema
  • Todos los permisos de Gerente y Usuario
🎯
Gerente
Código interno: manager
  • Ver y gestionar todas las cotizaciones de todos los usuarios
  • Exportar CSV de todas las cotizaciones
  • Crear y gestionar sus propias cotizaciones
  • No puede acceder a la gestión de usuarios
  • No puede eliminar cuentas de otros usuarios
👤
Usuario
Código interno: user
  • Crear, ver, editar y eliminar sus propias cotizaciones
  • Exportar sus cotizaciones a CSV
  • No puede ver las cotizaciones de otros usuarios
  • No puede acceder al panel de administración
  • No puede gestionar usuarios
⚠️
Credenciales predeterminadas

La cuenta de administrador creada durante la configuración inicial usa usuario: admin y contraseña: admin123. Cambia esta contraseña inmediatamente después del primer inicio de sesión en producción.

Capítulo 3.1

Crear un Nuevo Usuario

Haz clic en el botón + Nuevo Usuario en la página de Gestión de Usuarios para abrir el modal de creación.

CampoRequeridoNotas
user_nameSíIdentificador de inicio de sesión único (p. ej., jperez). No se puede cambiar después de la creación. Sin espacios.
real_nameSíNombre completo que se muestra en la interfaz y en las cotizaciones
emailSíDebe ser un correo único y válido. Se usa también para iniciar sesión.
passwordSíMínimo 6 caracteres. Se almacena como hash bcrypt — nunca en texto plano.
phone_numberNoTeléfono de contacto (opcional, visible en la tabla de usuarios)
roleSíSelecciona Administrador, Gerente o Usuario. Ver Capítulo 2 para diferencias de permisos.
  1. 1

    Haz clic en "Nuevo Usuario"

    El modal de creación se abre con un formulario vacío.

  2. 2

    Llena los campos requeridos

    Ingresa nombre de usuario, nombre completo, correo electrónico y una contraseña temporal. El teléfono es opcional.

  3. 3

    Selecciona el rol apropiado

    Haz clic en una de las tres tarjetas de rol (Administrador, Gerente, Usuario). La tarjeta seleccionada se resalta con borde morado.

  4. 4

    Haz clic en "Crear usuario"

    La cuenta se crea de inmediato. Comparte el nombre de usuario y la contraseña temporal con el usuario de forma segura.

🔒
Buenas Prácticas de Seguridad

Establece una contraseña temporal y pide al usuario que la cambie en su primer inicio de sesión. No reutilices contraseñas entre cuentas.

Capítulo 3.2

Haz clic en el botón Editar de cualquier fila en la tabla de usuarios para abrir el modal de edición. El formulario viene pre-rellenado con los valores actuales.

No puedes editar el estado activo de tu propia cuenta (el toggle está deshabilitado para el admin actualmente conectado). Esto previene bloquearse accidentalmente del sistema.

Capítulo 3.3

Desactivar y Eliminar Usuarios

Hay dos formas de retirar el acceso de un usuario: desactivación (reversible) y eliminación (permanente).

Desactivar un Usuario

Haz clic en el badge verde Activo en la tabla de usuarios para cambiarlo a Inactivo. El usuario no podrá iniciar sesión, pero su cuenta y todas sus cotizaciones permanecen intactas.

💡

Prefiere desactivar en lugar de eliminar para empleados que dejan la empresa. Sus cotizaciones históricas siguen accesibles para gerentes y administradores, preservando registros importantes del negocio.

Eliminar un Usuario

Haz clic en el botón rojo Eliminar en la fila del usuario. Aparecerá un cuadro de confirmación mostrando el nombre y nombre de usuario. Haz clic en Eliminar para borrar permanentemente la cuenta.

🚨
La eliminación es permanente

Eliminar una cuenta de usuario no puede deshacerse. Todas sus cotizaciones permanecerán en el sistema atribuidas a su ID de empleado, pero ya no podrán iniciar sesión y su información de perfil será removida. El botón eliminar no está disponible para el administrador actualmente conectado.

Capítulo 4

Gestionar Todas las Cotizaciones (Vista Admin)

A diferencia de los usuarios regulares que solo ven sus propias cotizaciones, los Administradores y Gerentes ven todas las cotizaciones de todos los agentes en la Lista de Cotizaciones.

Vista Admin/Gerente — se muestran todas las cotizaciones de todos los agentes

Desde /cotizaciones, los admins pueden:

  • Ver, editar, duplicar y eliminar cualquier cotización independientemente de quién la creó
  • Buscar y filtrar entre todos los nombres de clientes, estados y fechas
  • Exportar el conjunto completo de datos a CSV para reportes
ℹ️

La lógica del servidor verifica automáticamente el rol del usuario en cada llamada a la API. Admins y Gerentes reciben datos sin filtrar; Usuarios regulares reciben solo sus propios registros.

Capítulo 4.1

Exportar y Reportes

La exportación CSV permite extraer todos los datos de cotizaciones a una hoja de cálculo para análisis, reportes o archivo.

Exportar desde la Interfaz

En la página de Cotizaciones, haz clic en Exportar CSV. La descarga respeta los filtros activos — si quieres todas las cotizaciones, limpia todos los filtros primero.

Exportar via API

Capítulo 7

Referencia de API

La aplicación expone una API REST bajo /api. Todos los endpoints requieren una cookie de sesión válida (establecida por el endpoint de inicio de sesión).

Autenticación

POST/api/auth/login — Iniciar sesión. Body: { username, password }
GET  /api/auth/me — Obtener info de la sesión actual (id, rol)
POST/api/auth/logout — Cerrar sesión y limpiar cookie

Panel de Control

GET  /api/dashboard — Retorna estadísticas: totals, thisMonth, growth, expiringSoon, recentQuotes, monthlyTrend

Cotizaciones

GET  /api/cotizaciones — Listar cotizaciones (paginado). Params: page, search, status, sortBy, sortOrder, limit
GET  /api/cotizacion/[id] — Obtener una cotización con todos sus datos anidados
POST/api/cotizacion/[id] — Crear o actualizar una cotización (upsert)
DEL  /api/cotizacion/[id] — Eliminar cotización (Admin/Gerente: cualquiera; Usuario: solo las propias)
POST/api/cotizacion/[id]/duplicate — Crear copia de la cotización como nuevo borrador
GET  /api/cotizaciones/export — Descargar cotizaciones filtradas como archivo CSV

Usuarios

GET  /api/users — Listar todos los usuarios. Solo Admin.
POST/api/users — Crear nuevo usuario. Solo Admin. Body: { user_name, real_name, email, password, role, phone_number? }
PUT  /api/users/[id] — Actualizar campos del usuario. Solo Admin.
DEL  /api/users/[id] — Eliminar cuenta de usuario. Solo Admin. No puede eliminar la propia cuenta.

Inicialización de Base de Datos

GET  /api/init — Verificar si las tablas existen y retornar estado de la base de datos
POST/api/init — Crear todas las tablas y el usuario administrador por defecto

Capítulo 9

Instalación Inicial

Sigue estos pasos para configurar el sistema de Lobato Tours desde cero en una nueva máquina.

  1. 1

    Prerrequisitos

    Instala Node.js (v18+), npm y Docker Desktop en el servidor o máquina de desarrollo.

  2. 2

    Clonar repositorio e instalar dependencias

    Ejecuta npm install en el directorio del proyecto para instalar todos los paquetes de Node.js.

  3. 3

    Crear el archivo .env

    Copia las variables de entorno del Capítulo 5 en un nuevo archivo .env en la raíz del proyecto. Actualiza NEXTAUTH_SECRET con un valor aleatorio robusto.

  4. 4

    Iniciar el contenedor de base de datos

    Ejecuta npm run docker:up. Espera unos segundos para que PostgreSQL esté listo.

  5. 5

    Iniciar el servidor de desarrollo

    Ejecuta npm run dev. La aplicación inicia en http://localhost:3000.

  6. 6

    Inicializar la base de datos

    Visita http://localhost:3000. Si las tablas no existen, envía una solicitud POST a /api/init (o ejecuta npm run init-db). Esto crea todas las tablas y la cuenta de administrador por defecto.

  7. 7

    Iniciar sesión y cambiar la contraseña del admin

    Inicia sesión con admin / admin123. Ve a Gestión de Usuarios y edita la cuenta de administrador para establecer una contraseña segura de inmediato.

🚀
Configuración Automatizada

Ejecuta npm run setup para ejecutar los pasos 4–6 automáticamente con un solo comando.

Capítulo 10

Solución de Problemas

Problemas comunes y sus soluciones.

🔴 No se puede conectar a la base de datos

  • Ejecuta docker ps para confirmar que el contenedor está corriendo
  • Verifica que DB_PORT en .env coincida con el puerto del host en docker-compose (5430)
  • Verifica conflictos de puerto: lsof -i :5430
  • Ejecuta npm run docker:logs para ver errores de inicio de PostgreSQL

🟡 Tablas no creadas / "relation does not exist"

  • Envía POST /api/init para crear todas las tablas
  • O ejecuta: npm run init-db

🟡 Inicio de sesión falla con credenciales correctas

  • Verifica que NEXTAUTH_SECRET esté configurado en .env
  • Limpia las cookies del navegador y vuelve a intentar
  • Confirma que NEXTAUTH_URL coincida con la URL que estás usando en el navegador

🟡 /admin/users redirige al Panel de Control

  • Tu cuenta no tiene el rol de Administrador
  • Inicia sesión con una cuenta Admin, o pide a otro admin que actualice tu rol

🟢 Errores de permisos en script de inicio

  • Ejecuta: chmod +x scripts/start-dev.sh
Capítulo 11

Notas de Seguridad

Prácticas clave de seguridad para operar el sistema de Lobato Tours.

Autenticación y Sesiones

  • Las sesiones se almacenan del lado del servidor, firmadas con NEXTAUTH_SECRET. Usa una clave aleatoria de mínimo 32 caracteres en producción.
  • Las contraseñas se hashean con bcrypt antes de almacenarse. Las contraseñas en texto plano nunca se registran ni almacenan.
  • Las verificaciones de rol se aplican en cada llamada de API del lado del servidor — no pueden eludirse modificando cookies o URLs.

🛡️
Datos Sensibles

Los datos de cotizaciones pueden contener información personal de clientes (nombres, teléfonos, correos). Asegúrate de que el servidor de producción cumpla con las regulaciones de protección de datos aplicables (p. ej., LFPDPPP en México).
