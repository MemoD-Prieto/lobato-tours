Administrator Overview

This guide is for system administrators of the Lobato Tours Quotation System. It covers every admin feature in depth: user management, the dashboard metrics, quote oversight, PDF generation, CSV export, the database schema, and the full REST API.

Chapter 2

Roles & Permissions

The system uses three role levels stored in the empleado.role column. Role is checked server-side on every API call — it is never trusted from the client.

👑
Administrator — internal code: admin
  • Full access to every quote in the system, regardless of who created it
  • Access /admin/users — create, edit, deactivate, and delete user accounts
  • Call POST /api/init to initialize or re-seed the database
  • Export all quotes across all agents via /api/cotizaciones/export
  • All manager and user capabilities listed below
  • Cannot delete or deactivate their own account (self-protection lock)
🎯
Manager — internal code: manager
  • View, edit, duplicate, and delete every quote from every agent
  • Export the full CSV dataset (all agents, all statuses)
  • See the full dashboard statistics including all-agent totals
  • Create and manage their own quotes
  • Cannot access /admin/users — redirected to dashboard
  • Cannot call POST /api/init
  • Cannot create, edit, or delete any user account
👤
User — internal code: user
  • Create, view, edit, duplicate, and delete their own quotes only
  • Export a CSV of their own quotes only
  • Generate PDFs for their own finished quotes
  • The Quotes List only returns quotes they created — other agents' data is invisible
  • Cannot access /admin/users
  • Cannot call any user management API endpoints

How Role Changes Take Effect

When you change a user's role in the admin panel, the change is applied immediately to their database record. The effect kicks in on their next page load or API request — their current browser session retains the old role until they refresh. For a same-session role downgrade to take effect immediately, the user would need to log out and back in.

⚠️
Default credentials — change immediately

The database seed creates one admin account: username: admin, password: admin123. This password is stored as a bcrypt hash — but the plaintext default is well-known. Change it in User Management the moment the system is deployed.

Chapter 3

Dashboard & Metrics

The dashboard at / is the home screen for all roles. Admins and Managers see system-wide totals; regular Users see only their own data. All numbers are calculated live on each page load by GET /api/dashboard.

Stat Cards

Four cards appear at the top of the dashboard. Each card shows a count and a trend indicator.

CardWhat it countsServer-side calculation
Total Quotes All quotes ever created in the system (or by this user for the User role) Cotizacion.count() — no date filter, no status filter
Finished Quotes where finished = true Cotizacion.count({ where: { finished: true } })
Drafts Quotes where finished = false Derived: totalAll − totalFinished
This Month Quotes created since the 1st of the current calendar month (midnight) creation_date >= startOfMonth where startOfMonth = new Date(year, month, 1)

Month-over-Month Growth

Below the stat cards a percentage growth figure is shown. The formula is:

growth = round( (thisMonthCount − lastMonthCount) / lastMonthCount × 100 )

# Edge cases:
# If lastMonth = 0 and thisMonth > 0 → growth = 100%
# If lastMonth = 0 and thisMonth = 0 → growth = 0%
# Negative result = fewer quotes than last month

Last month is the complete previous calendar month (from its first day 00:00:00 to its last day 23:59:59).

Monthly Trend Chart

A bar chart shows quote volume for the last 6 calendar months. Each bar is a count of quotes whose creation_date falls within that month. Month labels are in Spanish short format (e.g., ene 25, feb 25) because the dashboard uses the es-MX locale for formatting. The chart helps you spot seasonal peaks and slowdowns at a glance.

Expiring Quotes Warning

If any draft quotes have a valid_until date within the next 7 calendar days, a yellow warning banner appears beneath the stat cards. The count shown is the number of such quotes.

# Condition:
valid_until BETWEEN today AND (today + 7 days)
AND finished = false

Clicking the warning banner opens the Quotes List pre-filtered to show those expiring drafts so you can act on them immediately. Finished quotes are excluded because they are already complete.

Recent Quotes Table

The bottom of the dashboard shows the 5 most recently created quotes, sorted newest-first by creation_date. Each row displays the quote ID, customer name, contact, creation date, and status badge. Clicking the arrow button navigates directly to that quote's detail page.

ℹ️
Dashboard does not auto-refresh

All metrics are loaded once when the page mounts. Reload the page to get updated counts after other agents create or finalize quotes.

Chapter 4.3

Deactivating & Deleting Users

There are two ways to remove a user's access: deactivation (reversible) and deletion (permanent).

Deactivating a User

Click the green Active status badge in the users table to toggle it to Inactive. The user will be prevented from logging in, but their account and all their quotes remain intact.

💡

Prefer deactivation over deletion for employees who leave the company. Their historical quotes remain accessible to managers and admins, preserving important business records.

Deleting a User

Click the red Delete button on a user's row. A confirmation dialog will appear showing the user's name and username. Click Eliminar to permanently delete the account.

🚨
Deletion is permanent

Deleting a user account cannot be undone. All their quotes will remain in the system attributed to their employee ID, but they will no longer be able to log in and their profile information will be removed. The delete button is not available for the currently logged-in admin.

Chapter 5.1

Search, Filter & Sort

Search Bar

The search box runs a case-insensitive (ILIKE) partial-match query against three fields simultaneously:

WHERE customer_name ILIKE '%{query}%'
OR customer_contact ILIKE '%{query}%'
OR customer_contact2 ILIKE '%{query}%'

You can search by client name, primary phone/email, or secondary phone/email. Partial matches work — entering "garcia" will find "Ana García" and "Luis Garciaparra". The search is accent-insensitive at the database collation level.

Status Filter

Filter valueWhat it shows
all (default)Both finished and draft quotes
finishedOnly quotes where finished = true
draftOnly quotes where finished = false

Sort Options

Sort fieldNotes
id (default)Newest quote first by default (DESC)
creation_dateOrder by when the quote was created
finishedGroups finished and draft quotes together

Each sort column can be toggled ASC/DESC by clicking the column header. The direction is passed as ?sortOrder=ASC|DESC to the API.

Pagination

Results are paginated at 10 quotes per page by default. The API returns a pagination object:

{
  "currentPage": 1,
  "totalPages": 7,
  "totalCount": 68,
  "limit": 10,
  "hasNext": true,
  "hasPrev": false
}

Page controls at the bottom of the table let you jump to any specific page number, or use Previous/Next buttons.

💡

Tip: Filters and search are cumulative. You can search "cancun" AND filter to "finished" to see only finalized Cancún quotes. Clear the search field and reset the status filter to "all" before exporting to CSV if you want the full dataset.

Chapter 6

PDF Generation

The PDF is generated server-side by the Node.js PDFKit library. It is a letter-size (8.5 × 11 in) two-page document streamed directly to the browser — no file is saved to disk. The endpoint is GET /api/cotizacion/[id]/pdf.

How to Generate a PDF

There are two entry points:

  1. 1

    From the Quote Detail page

    Click the red PDF button in the header. Opens in a new browser tab.

  2. 2

    From the Quote Wizard — Summary step (Step 10)

    A red Export PDF button appears once the quote has been saved with an ID and marked Finished.

The direct URL format is: http://[host]/api/cotizacion/[id]/pdf. This URL can be shared directly with a client — they can open it in any browser without logging in (the PDF endpoint does not require authentication, making it safe to share).

Cost Calculation Logic

The subtotal is the sum of all service costs. Each service's contribution:

Flight: (base_fee + iva + luggage_check + airport_right_of_use + suitcases_tax) × num_personas
Cruise: precio × num_personas
Ferry: precio × num_personas
Tickets: precio × cantidad (or × num_personas if cantidad is 0)
Transfer: amount (flat total, no per-person multiply)
Insurance: costo (flat total)
Data SIM: costo (flat total)
Visa: costo (flat total)
Package: package_price (flat total)
Hotel: SUM of (habitacion.price + habitacion.iva) for all rooms

commission_amount = subtotal × (commission_pct / 100)
total = subtotal + commission_amount
per_person = total / total_traveler_count

If a service's num_personas is 0 or null, it falls back to the quote's total traveler count.

Chapter 7

CSV Export Reference

The CSV export allows you to pull all quote data into a spreadsheet for analysis, reporting, or archiving.

Exporting from the UI

On the Quotes List page, click Export CSV. The download respects active filters — search text and status filter are both applied. To export the full dataset, clear all filters first, then click Export CSV.

Exporting via API

GET/api/cotizaciones/export

# Optional query parameters (same as the Quotes List):
?status=all|finished|draft
?search=customer_name_or_contact

The response is Content-Type: text/csv; charset=utf-8 with a UTF-8 BOM prepended so Excel opens it correctly without an import wizard. The filename is cotizaciones_YYYY-MM-DD.csv using today's date. All rows are sorted newest-first by creation_date.

API Reference

All API endpoints live under /api. Every request must include a valid authToken session cookie (set automatically by the login endpoint). The cookie is HttpOnly and SameSite=Strict. Role is read from the session on each request — not from any header or body field.

Chapter 12

Troubleshooting

Symptoms, causes, and step-by-step resolutions for the most common issues.

🔴 Cannot connect to database / "ECONNREFUSED"

  • Run docker ps — the lobato-postgres container must be listed as Up. If it's missing, run npm run docker:up.
  • Check DB_PORT in .env matches the docker-compose host port (5430 by default). The container's internal port is 5432 — don't confuse the two.
  • Check for port conflicts: lsof -i :5430 (macOS/Linux) or netstat -ano | findstr :5430 (Windows). Another app may be binding that port.
  • Run npm run docker:logs to see PostgreSQL startup errors (e.g., data directory corruption, auth issues).

🔴 PDF is blank or shows "Not found"

  • The quote ID in the URL does not exist in the database — verify the quote was saved (has a numeric ID, not "new").
  • Font files may be missing from public/assets/fonts/. PDFKit will throw an error if Sans-Regular.ttf is not found. Check the server terminal for errors.
  • The logo file path public/assets/images/logos/logo-lobato-2.jpg does not exist — the PDF still generates but without the logo. Not a fatal error.

🟡 Tables not created / "relation does not exist"

  • The database container is running but the schema was never initialized. Send POST /api/init from a browser (or with curl/Postman) to create all tables.
  • Alternatively run the npm script: npm run init-db
  • If the error persists after init, the DB_NAME in .env may point to the wrong database. The default is postgres.

🟡 Login failing with correct credentials

  • Account is inactive — the active field was set to false. An admin must toggle it back to Active in User Management.
  • Wrong password — the default password for the seed admin is admin123 (case-sensitive). If it was changed and forgotten, update the bcrypt hash directly in the database.
  • NEXTAUTH_SECRET missing — the session cookie can't be signed. Set a value in .env and restart the server.
  • Clear all browser cookies for localhost:3000 and try again in a private window to rule out stale session issues.

🟡 /admin/users redirects to dashboard

  • Your session's role is not admin. The page checks /api/auth/me on load and redirects immediately if role ≠ admin.
  • Log in as an admin account, or ask another admin to change your role in User Management. The role change takes effect on your next page load.

🟡 CSV export opens as garbled text in Excel

  • The file includes a UTF-8 BOM (\uFEFF) precisely to prevent this. If Excel still shows garbled text, use Data → From Text/CSV in Excel and select UTF-8 encoding during the import wizard.
  • Google Sheets: File → Import → select the downloaded CSV file. Encoding auto-detects correctly.

🟡 Quote wizard loses data between steps

  • Auto-save fires on every Next/Previous/dot click. If the server is unavailable (DB down, dev server crashed), the save call fails silently. Check the browser's Network tab for failing POST /api/cotizacion/[id] calls.
  • If the quote was never saved (still shows ID "new"), the first save creates the record. All subsequent steps update it. Data is not lost unless the browser tab is closed before the first step is saved.

🟢 Permission error on startup scripts

  • Make the script executable: chmod +x scripts/start-dev.sh
  • On Windows, run the commands in package.json manually in PowerShell.
Chapter 13

Security Notes

Security practices for operating the Lobato Tours system in production.

Authentication & Session Model

Login calls POST /api/auth/login, which verifies the password with bcrypt.compare(), then writes a signed authToken cookie. The cookie is HttpOnly (not accessible to JavaScript), SameSite=Strict (blocks CSRF), and scoped to the app's path. The payload contains the user ID and role, signed with NEXTAUTH_SECRET using a JWT-style signature.

Every subsequent request reads and verifies that cookie on the server. The role stored in the token is cross-checked against empleado.active on sensitive operations — a deactivated user's existing cookie will be rejected on their next API call.

Password Storage

Passwords are hashed with bcrypt (cost factor 10) before being stored in the password_hash column. Plaintext passwords are never logged, stored, or returned by any endpoint. The default password admin123 is seeded as a bcrypt hash — not the plaintext string — but it is still a well-known value and must be changed immediately in any non-development deployment.

To manually reset a forgotten admin password directly in the database:

# Generate a new bcrypt hash (e.g., for "newpassword"):
node -e "const b=require('bcryptjs');b.hash('newpassword',10).then(h=>console.log(h))"

# Then update in psql:
UPDATE empleado SET password_hash = '<hash>' WHERE user_name = 'admin';

Role Enforcement

Every API handler that requires elevated permissions calls an auth check helper at the top of the function. The check pattern is:

  1. Read the authToken cookie from the incoming request.
  2. Verify the JWT signature with NEXTAUTH_SECRET.
  3. Extract the user ID and role from the payload.
  4. If the endpoint requires admin: reject with 403 Forbidden if role ≠ "admin".
  5. If the endpoint is user-scoped (e.g., delete own quote): reject with 403 if the record's employee_id ≠ session user ID (unless admin/manager).

This means a User-role session token cannot access admin endpoints even if the URL is known — the server always validates server-side before touching the database.

PDF URL Sharing

The PDF endpoint (GET /api/cotizacion/[id]/pdf) intentionally does not require an auth cookie. This allows agents to share the direct PDF URL with clients. The trade-off is that anyone who knows a quote's numeric ID can view that quote's PDF. IDs are sequential integers — be aware that a motivated user could enumerate them. If this is a concern in production, add token-based URL signing or restrict access behind auth.

Customer Data & Privacy

Quotes contain personal customer data: full names, phone numbers, and in some cases secondary contact information. This data is subject to Mexico's LFPDPPP (Ley Federal de Protección de Datos Personales en Posesión de los Particulares). Ensure the production server:

  • Is served over HTTPS (TLS 1.2 minimum) so data in transit is encrypted.
  • Has automated database backups with encryption at rest.
  • Does not expose the PostgreSQL port (5430) to the public internet.
  • Has a defined data retention and deletion policy.
